# MCPwn — CLAUDE.md (repo build instructions)

> Self-contained project: no other project or repo is a dependency, source, or reference. Correctness = tests against each attack's known outcome; quality = the Definition of Done below, enforced in CI. Measured metrics (P/R, robustness) are reported results, not invented thresholds. This file is kept in sync with the code every wave; its claims must be **true in practice**, not just present on paper.

## What MCPwn is

Standalone, deployed web app that red-teams an MCP-tool-using agent against the OWASP Top 10 for Agentic Applications (2026). **The competitive product: point your own MCP agent at us → live red-team it against the Core-7 → get a trustworthy report from a detector whose accuracy is *measured* (leakage-separated P/R).** Two access modes: a no-key **sample playback** (a curated real run — the trailer) and **live red-teaming** (the tool).

**MCPwn IS the MCP server; the user's agent connects TO us** ([ADR-0006](docs/adr/0006-mcpwn-is-the-mcp-server.md)). Per run we host an MCP endpoint that serves the attack's `Environment` — the Core-7 tools, some deliberately over-broad or mis-described, plus seeded memory and prompts — and we record every `tools/call` the agent chooses to make into the `Trace`. **You cannot poison what you do not serve:** ASI01/02/04/05/06 are all staged through the tool surface, so serving it is what makes them stageable at all. `Scenario.taskGoal` is delivered **out of band** (a published MCP prompt preferred, paste as fallback), because MCP has no server-to-agent "here is your goal" message. **`agent_reasoning` is not observable** from the server side and is never synthesized; `task_complete` is **inferred** and labelled as such.

The user still brings the agent and pays its inference; **they no longer hand us its endpoint or key** — we never call their agent, so we hold no credential of theirs. The **judge is the fixed, validated, operator-provided detector — LOCKED** and never user-swappable (the measured accuracy only holds for the validated judge config). Live runs are **gated** (email-OTP sign-in + a **per-account LIFETIME free allowance**, default ~3 runs total, NOT per day) with a cheap validated judge, so operator judge cost stays a few cents per run ([ADR-0007](docs/adr/0007-access-and-cost-model.md)). Hero: live attack replay. Supporting: per-model robustness leaderboard + engineer-ready fix reports.

## Stack

- Next.js (App Router) + TypeScript, deployed on Vercel. **Production is `https://mcpwn.dev` — the canonical URL**, and the origin page metadata resolves against (`NEXT_PUBLIC_SITE_URL`). The Vercel-generated `*.vercel.app` domain still resolves but is never the stated URL.
- UI: Tailwind + shadcn/ui on the **Base UI** engine (not Radix — unmaintained). DTCG two-tier design tokens (primitives → semantic aliases) → CSS variables → Tailwind.
- Persistence: **Supabase Postgres** behind a repository port — **exactly one run store**, `RunRepository` in `src/data/run-repository.ts`, keyed `(userId, uuid)` and owner-scoped by RLS; a Supabase adapter (via the Supabase JS client, not a raw `DATABASE_URL`) for prod and an in-memory adapter for tests/offline. The earlier second store (`src/persistence/*`, keyed by bare `runId`, with a provider-agnostic `DATABASE_URL` postgres adapter) was **superseded and deleted** — two semantically incompatible stores meant a live run could be wired to the wrong one.
- Auth: **Supabase Auth** — **emailed one-time code (OTP)** sign-in (optional GitHub/Google OAuth) — gates live runs. **Code-only by design: the email carries a code and NO clickable link**, because a link and a typed code share one token, so a corporate scanner that pre-fetches the URL spends it and breaks the code too. Two steps in one browser: `requestEmailCode` (`signInWithOtp`) then `verifyEmailCode` (`verifyOtp`). **`/auth/callback` exists for GitHub OAuth only** and is the sole remaining PKCE consumer. **The send must go through a non-PKCE client** (`@supabase/ssr` forces `flowType: "pkce"`, under which GoTrue stores a flow-state code instead of the OTP hash and no emailed code can ever verify; `createOtpSenderSupabase()` in `src/lib/supabase/server.ts` carries the full trace). **The code length is a Supabase project setting (6 to 10), never a hardcoded constant** — it is mirrored in `NEXT_PUBLIC_EMAIL_OTP_LENGTH` and every human-visible mention derives from it. Config is env-only: `SUPABASE_URL`, `SUPABASE_ANON_KEY` (public), `SUPABASE_SERVICE_ROLE_KEY` (secret, **server-only**), `DATABASE_URL` (Supabase); secrets never logged, never persisted in plaintext.
- External access behind domain-named ports: `JudgeModelPort`, `McpTargetPort` — HTTP adapters validate their own creds lazily, so the offline app boots with none. **Under [ADR-0006](docs/adr/0006-mcpwn-is-the-mcp-server.md) the live agent path is INBOUND** (module 1 hosts the MCP server the agent connects to); `McpTargetPort` keeps the narrower job of probing a target MCP *server* (the ASI02 / ASI05 surfaces) and supplying the shared transport / JSON-RPC / Zod / retry layer.

## UI & design

- **The design is the DEFAULT reference, not immutable.** [`design-review/MCPwn Sentinel v2.dc.html`](design-review/) is the **Wave C reference** for screens, layout, copy, states, and mobile. It was designed in Claude Design (that role is complete). We implement it in code, where Impeccable's method both works on it and measures it. It is the default we start from, **not a frozen artifact**: when Impeccable flags one of its moves, the finding is adjudicated (kept with a documented reason, or surfaced as a proposed change for sign-off), never overwritten by reflex and never auto-vetoed. See [ADR-0004](docs/adr/0004-design-frozen-and-impeccable-as-craft-gate.md).
- **THE PRINCIPLE — the design is the default reference; token roles DESCRIBE it, they do not silently redesign it.** If a *token role* and the design disagree, the design is the default and the role is re-examined. (Two spec errors proved this: a 65–75ch role-level measure cap produced dead side-margins by fighting the design's own columns, and pinning DISPLAY to mono rewrote the design's sans numerals. Both were "good typography" overruling the actual design.) Impeccable's *design* findings are different in kind: they may legitimately propose changing a design move. A flag becomes a **proposed change surfaced for sign-off** with the finding and our reason, not a unilateral overwrite and not an automatic veto. See ADR-0004.
- **The THREE-ROLE type model** (built + measured; DTCG roles in `src/app/globals.css`, locked by `tests/unit/app/tokens.test.tsx`):
  - **READING** — sans · 17 body / 18 lead / 20 · 28 · `clamp(32px, 5cqi, 44px)` · **every sentence a human reads**.
  - **INSTRUMENT** — mono · 12–13px · **telemetry only**: labels, chips, metadata, cues, column/row headers.
  - **DISPLAY** — **family per the frozen design** · 15 / 20 / 28 / 40 · values that **are** the focus (leaderboard cell values + OVERALL, hero stats, the replay step numeral).
  - Hard rules: **prose NEVER wears an INSTRUMENT role** (a blocking review failure); roles stay **measurably** distinct (`--display-sm` and `--reading-body` both above the INSTRUMENT ceiling); headline sizing is **`cqi`, never `vw`** (the column tracks the command deck, not the viewport); a tri-state **band colour overrides DISPLAY at zero specificity** via `:where()`; READING pins **no measure** (the design owns layout width).
- **Impeccable is the design METHOD for all UI work** (impeccable.style; an opinionated design _partner_, not a validator — push back with a reason and it works with you). It runs on the built source, not the mockup, through the site's **four-phase loop**:
  - **START** — `init` (captures `PRODUCT.md` + `DESIGN.md`; skipping it is the documented cause of generic-SaaS output), `shape`, `craft`.
  - **ITERATE** — `polish` · `typeset` · `layout` · `colorize` · `animate` · `bolder` · `quieter` · `live` · `critique` (refine in place, by dimension or in the browser).
  - **POLISH** (on a narrow target) — `audit` (accessibility · performance · theming · responsive · anti-patterns, scored **0–4**, findings **P0–P3**), `clarify`, `harden`.
  - **MAINTAIN** — `extract`, `document`.
  - Register (BRAND vs PRODUCT) is picked per task from the cue + `PRODUCT.md`/`DESIGN.md` (BRAND: Home, Sign-in · PRODUCT: Connect, Replay, Leaderboard, Findings, Threats). It inherits our DTCG tokens; it never introduces its own. **`npx impeccable detect src/` is the BLOCKING CI slop gate**; `/impeccable audit` is the per-screen verification.
  - **Adjudication (precedence A, per [ADR-0004](docs/adr/0004-design-frozen-and-impeccable-as-craft-gate.md)):** every screen runs the loop, then `audit`; each finding that touches a design move is either **pushed back with a documented reason** (pre-decided KEEPs: the functional tri-state glow; the real OWASP 01–10 numbering) or **accepted and surfaced as a proposed change for sign-off** (e.g. per-section eyebrows; the generic hero-metric _treatment_ of the measured numbers — the numbers stay). Each screen PR lists every finding and its disposition.
- **Measurement.** Verification is `/impeccable audit` (accessibility · performance · theming · responsive · anti-patterns, 0–4, P0–P3) plus `@axe-core/playwright` and Lighthouse CI (real-Chrome CWV budgets). Every screen reports its **type table (computed size/colour/contrast per role) + CWV + axe + its audit findings and dispositions**. **A screen does not get a PR without its numbers.**
- **Copy:** count **magnitudes**, never **evidence** — never animate step numbers, run IDs, severities, or amounts quoted from a trace. **No em dashes in UI copy.**
- **Aesthetic:** **J.A.R.V.I.S.-style living HUD** on a dark control-room base — dark navy (not pure black), thin glowing line-work, arc/ring motifs, translucent panels, monospace (Geist Mono) technical readouts. **Tri-state status color: cyan (normal) · amber (caution/elevated) · red (breach/compromise).** WCAG 2.2 AA contrast on all text; status is glow **plus** label/icon, never color-only. The glow palette lives in the DTCG primitive token tier (theme swap, not a rebuild).
- **Fourth state — `--status-inert` (neutral/muted, "not measurable"):** a separate, desaturated state for things that are **out of scope / not measured** (e.g. the ASI07/08/09 rows on the Threat Model / Coverage board). It is **explicitly NOT a tri-state member** and is **NEVER red** — red is reserved for an actual breach, and spending it on an uncovered category would corrupt the signal language (a not-tested category is not a failing one). Like every other state it carries an **icon + label**, never color alone. See [ADR-0003](docs/adr/0003-core-7-scope-and-measurability-bar.md).
- **Screens:** (A) Run Setup · **(B) Live Attack Replay** (hero) — a step timeline with play/pause/step/scrub/speed, typed color-coded nodes (+ icon/label), the compromise step badged from `verdict.stepId`, a step-detail panel (payloads + memory before/after diff), and the detector rationale pinned to the compromise step, with fix-report export · (C) Robustness Leaderboard heatmap · (D) Findings / fix-reports · **(E) Threat Model / Coverage** (`/threats`) — the OWASP Agentic Top 10 as a coverage board: the **Core-7** covered (tri-state) and **ASI07/08/09 marked not-measurable** via `--status-inert` (never red), each linked to the [measurability bar](docs/adr/0003-core-7-scope-and-measurability-bar.md) — **plus any additional views that strengthen the tool (directive 7).**
- **Access & routes (competitive vision):** a **Home / landing** (`/`) — the pitch (bring-your-own-agent red-teaming + the *measured-detector* claim) + the sample-run trailer + CTAs (*Try the sample* · *Connect your agent*); **Connect / Run Setup** — sample mode, or **live**: **point your agent at OUR MCP endpoint** (we issue a per-run URL + per-run token; the user never gives us an endpoint or a key), pick Core-7, **deliver the task goal out-of-band** (published MCP prompt preferred, paste fallback), then the panel waits on the real connection state; detector shown **BLIND · locked**. Home is the front door; the app screens sit behind it. **Routes:** `/` (home/landing) · `/sign-in` (Supabase Auth · emailed one-time code · gates live runs) · `/connect` (run setup — sample, or live against our hosted MCP endpoint) · `/runs/[id]` (live attack replay) · `/leaderboard` (robustness heatmap) · `/findings/[id]` (fix report) · `/threats` (threat model / coverage — Core-7 covered + ASI07/08/09 not-measurable).
- **Motion & interaction (restrained, alive):** the replay hero is the **Sentinel v2 orbital** — a clock-face where the 13 typed nodes are placed AROUND a ring by trig (so numbers never collide into a smear the way a flat row did), a **sweep line rotates to the active step**, tilted depth-ring ellipses imply a 3D core, and the centre carries the **STEP numeral** (band-coloured: cyan normal, amber complete, breach-red at the compromise). Serious instrument, not gamified — no gratuitous scanlines. **SVG + GPU-cheap CSS transforms/opacity only — no WebGL, no three.js / react-three-fiber / drei / GSAP** (those deps are dropped). ## Definition of Done (derived from current SE standards; every increment meets it)

- **Tests** — TDD Red→Green→Refactor (Kent Beck / [Fowler](https://martinfowler.com/bliki/TestDrivenDevelopment.html)); test pyramid unit>integration>e2e ([Fowler](https://martinfowler.com/articles/practical-test-pyramid.html)); **coverage threshold enforced in CI**; property-based tests (`fast-check`) for invariants (e.g. detector never emits a `stepId` absent from the trace). Deterministic LLM mocking for units; the live judge is statistical/gated.
- **CI/CD (GitHub Actions, push all branches + PR to main)** — install → lint → typecheck → unit(`--coverage`, threshold) → integration → build → e2e + `@axe-core/playwright` → Lighthouse CI (CWV budgets) → `audit-ci`. `main` protected; deploy-on-green to Vercel; PR previews. (Continuous delivery / [DORA](https://dora.dev/capabilities/continuous-delivery/).)
- **Pre-commit / pre-push** — husky + lint-staged + commitlint. **Pre-push is a fast local gate that validates the *commit being pushed*, not the working tree**: it checks out the pushed SHA into an isolated worktree (deps reused, never reinstalled), runs a fast **typecheck** there, and fails closed — so a dirty tree can't cry wolf, uncommitted work is never stashed or at risk, and it stays fast enough that it is never worth bypassing. It is deliberately *not* the full gate; **CI (which runs on every push) is the authoritative gate** (install → lint → typecheck → unit `--coverage` → build → e2e + axe → Lighthouse CWV → `impeccable detect` → `audit-ci`). "Done" for any screen = typecheck **and** unit **and** `detect` clean **and** `/impeccable audit` run with every finding dispositioned (pushed back with a reason, or accepted as a proposed change for sign-off) **and** measured numbers (type table + CWV + axe), not tests alone. **Confirm the branch's own CI is green before presenting a screen for sign-off** — "local unit passed" is not "the PR is green" (a flaky CLS once passed local checks while the PR's Lighthouse gate was red).
- **Security** — dependency audit; Zod input validation on all external inputs; no secret leakage; env-only config ([12-factor III](https://12factor.net/config)); **authz on live-run / run-control endpoints** (email-OTP sign-in + the per-account **lifetime** free allowance gate every live run — [ADR-0007](docs/adr/0007-access-and-cost-model.md)). **Abuse backstops** (defence in depth, not the primary control): email-verified OTP sign-in so an allowance cannot be reset with throwaway accounts, sign-up rate limiting, and a **global model-spend cap** whose trip makes live runs **pause gracefully** down the `resolveLiveDetector()` null fail-safe (a typed refusal the UI states plainly) rather than overspend — **the cap itself is DESIGNED, NOT BUILT; the fail-safe it pauses down exists as of Slice 2b** (`src/detector/resolve.ts`), so the seam is there and the cap is not. **The allowance is a TUNABLE DEFAULT read from config — never hardcode a numeral into copy**, and never state a specific free-run count until the enforcement actually honours it. **The allowance LOGIC exists and is NOT yet called:** `checkLiveRunAllowance()` (`src/runs/allowance.ts`) counts a user's runs from **account creation** (lifetime, never a rolling window) via `countRunsSince`, compares that to `LIVE_RUN_ALLOWANCE` (env-only, default 3, `0` disables free live runs), and returns a decision carrying a typed `LiveRunAllowanceError` (`ALLOWANCE_EXHAUSTED`) instead of throwing; `describeLiveRunAllowance()` is the ONE place the number becomes words. It has no production caller yet because the live-run entry point it guards is unbuilt (the MCP server we host), so the integration point is documented in the module rather than invented. **Run-endpoint credential handling ([ADR-0006](docs/adr/0006-mcpwn-is-the-mcp-server.md)):** we **do NOT hold the user's agent credentials** — we never call their agent, so there is no key of theirs to store, log or leak. Instead we **authenticate the INCOMING agent connection**: each run issues a **per-run, per-account token** that our MCP endpoint requires, used **server-side only**, transported over **HTTPS**, **never logged**, and **never persisted in plaintext**. Tokens are **scoped to one run and expire with it**, so a leaked token exposes one sandboxed run of fabricated attack content, never an account. **We are deliberately inviting a stranger's agent to connect to an endpoint we run, and the tools we serve are hostile by design** — treat that endpoint as inbound attack surface, with nothing real behind it. The operator-provided validated judge stays **LOCKED** and is never user-swappable. **Supabase config** (env-only): `SUPABASE_URL`, `SUPABASE_ANON_KEY` (public/client-safe), `SUPABASE_SERVICE_ROLE_KEY` (**secret · server-only** — never client-exposed, never logged, never persisted in plaintext), `DATABASE_URL` (Supabase Postgres).
- **Reliability** — error boundaries (`error.tsx`/`global-error.tsx`); typed errors; timeouts + bounded retries on external calls.
- **Observability** — structured logging; `/api/health`; runs + traces persisted/retrievable.
- **Accessibility** — WCAG 2.2 AA / POUR ([W3C](https://www.w3.org/WAI/standards-guidelines/wcag/)): `@axe-core/playwright` in CI + role/name unit assertions + `/impeccable audit` (accessibility dimension) (automation catches ~30–50%; not a substitute for manual AT).
- **Usability** — Nielsen's 10 heuristics ([NN/g](https://www.nngroup.com/articles/ten-usability-heuristics/)): visibility of system status (run progress), user control (stop/step a run), consistency, error prevention, recognition over recall, aesthetic/minimalist design.
- **Performance** — Core Web Vitals good @ p75 (LCP ≤ 2.5s, INP ≤ 200ms, CLS ≤ 0.1; [web.dev](https://web.dev/articles/vitals)) via Lighthouse CI (real-Chrome CWV budgets) + `/impeccable audit` (performance dimension); virtualize long lists. **CWV is verified over multiple runs (5 is the standard) under devtools throttling, never a single measurement** — one reading let a flaky ~0.22 CLS pass by luck; the multi-run throttled result IS the honest number.
- **Docs** — README + architecture diagram (Mermaid source kept as the reproducible/diffable canonical **plus a polished `archify` SVG render**) + a **leakage-barrier data-flow SVG** (`archify`); ADR log (`docs/adr/`); `.env.example`; CLAUDE.md + plan.md kept in sync and verified true.
- **Reproducibility** — clean clone → build/test/deploy; pinned deps + lockfile. **`package-lock.json` is a CROSS-PLATFORM artifact and is NEVER regenerated on Windows** (see the lockfile rule under Dependencies) — the dev machine is Windows and CI is Linux, so a lockfile that installs here can still install nothing on the runner.

## Scope — Core-7 (OWASP Agentic Top 10 2026; genai.owasp.org)

ASI01 Agent Goal Hijack · ASI02 Tool Misuse and Exploitation · ASI03 Identity and Privilege Abuse · ASI04 Agentic Supply Chain Vulnerabilities · ASI05 Unexpected Code Execution (RCE) · ASI06 Memory & Context Poisoning · ASI10 Rogue Agents (v1 bounded to three single-run signatures).

**Why seven, not ten — the measurability bar (locked; [ADR-0003](docs/adr/0003-core-7-scope-and-measurability-bar.md)):** a category ships only if the compromise is (1) **observable** in the agent's own `Trace` steps, (2) inside **one bounded run**, (3) **anchorable** to a single offending step (`Verdict.stepId` — "compromised at step N, or not"), AND (4) has a **benign variant that scores not-compromised** (without it we can measure recall but never precision). ASI07 (Insecure Inter-Agent Communication — needs an agent-to-agent step type the Trace lacks), ASI08 (Cascading Agent Failures — OWASP defines it as the *propagation* of a fault, not the initial vulnerability, so there is no single step to anchor), and ASI09 (Human-Agent Trust Exploitation — completes inside a human's decision the trace can't observe) do not clear the bar under the current contract. Seven measured beats ten unmeasurable.

## Data contract (single source of truth; UI renders observable data only)

- `Trace` — OBSERVABLE only: `{ runId, target, model, category, steps[] }`; step types: attacker | agent_reasoning | tool_call | tool_result | memory_read | memory_write | task_complete. No labels.
- `GroundTruth` — HELD OUT: `{ compromised, stepId?, category }`, produced at construction; the detector NEVER receives it.
- `Verdict` — `{ runId, compromised, score, severity, category, rationale, stepId? }` (`stepId` present iff compromised).
- `RunResult` — a LIVE run's output: `{ runId, target, model, category, trace, verdict }`; no groundTruth (live runs are unlabeled).
- Attacks expose `build(variant) → { trace, groundTruth }` (detector validation) and `scenario(variant) → { taskGoal, environment }` (drive a live agent). Types via `z.infer`.

## Ground truth vs detector (leakage separation — the core invariant)

Standard ML anti-leakage: never let the model use information unavailable at prediction time; keep the label out of the features (target leakage — Kaufman et al. 2012, *Leakage in Data Mining*; train/test separation). Applied here: the observable `Trace` is the feature; the held-out `GroundTruth` is the label; the detector and UI see only the Trace. P/R compares detector verdicts to held-out ground truth on constructed fixtures; live runs are unlabeled — which is why the detector exists.

## Detector (module 4)

Blind LLM alignment-auditor (LlamaFirewall/AlignmentCheck style; arXiv 2505.03574): reads the whole Trace vs the task goal, classifies the Core-7 category, anchors the offending step. Trace/goal go in as untrusted, delimited data (never instructions; guards against judge-injection — JudgeDeceiver, arXiv 2505.13348). Structured output → Zod value-validation → typed `DetectorError`, never a raw crash. Low temperature (env), pinned model, empty-trace pre-check.

**The live judge (Slice 2b).** `createAnthropicJudge()` (`src/detector/anthropic-judge.ts`) is the HTTP `JudgeModelPort` — one `JudgeRequest` becomes one `POST {JUDGE_BASE_URL}/v1/messages` (Anthropic Messages API, `x-api-key` + `anthropic-version`), with the fixed rubric as `system` and the delimited untrusted trace as a single user message, so the injection boundary survives serialization. `model` and `temperature` are read off the request, not off the adapter's own config, so there is one source of truth for which model produced a measured number. Failures are typed `JudgeAdapterError`s (`CONNECTION_FAILED` · `TIMEOUT` · `HTTP_ERROR` · `MALFORMED_RESPONSE` · `EMPTY_RESPONSE`) with bounded exponential-backoff retries on 429/5xx and a per-request deadline; the key is a header and is interpolated into nothing. **`JUDGE_MODEL` must accept `temperature`** — the Claude 4.7+ and 5 families reject sampling parameters with a 400, and a pinned low temperature is part of what makes a measured P/R reproducible; `claude-haiku-4-5` is the intended cheap validated judge.

`resolveLiveDetector()` (`src/detector/resolve.ts`) is the **only consumer** of `JUDGE_BASE_URL` / `JUDGE_API_KEY`. **Measuring is a deliberate act: `npm run eval:measure`.** It drives `evaluateAll` over every labeled realization with the real judge, prints aggregate and per-category precision/recall with confusion counts, lists each disagreement with the held-out ground truth, and writes a dated report (judge model, temperature, N, elapsed) to a gitignored artifact. With no credential it exits non-zero rather than emitting a number nobody measured. **A P/R figure reaches a screen only from that report, carrying its provenance — "measured · N labeled fixtures · date" — and the number and its provenance move together or not at all.** A gated integration test (`tests/integration/eval-judge.live.test.ts`) exercises the same path and asserts the wire-level leakage barrier and stepId anchoring, but deliberately asserts **no** P/R value: a pinned number would either fail on ordinary model variance or quietly become the place the claim lives.

**THE LOCKFILE RULE — never regenerate `package-lock.json` on Windows.** `npm install` resolves the optional-dependency tree for the platform it runs on and PRUNES the entries it does not need, so a regeneration on this Windows dev machine silently drops the packages the **Linux** CI runner installs from: `lightningcss-linux-*` (Tailwind v4's engine), `@unrs/resolver-binding-linux-*` (the ESLint import resolver), and `fsevents`. `npm ci` on the runner then installs a tree with **no native binaries**, and the unit step fails on a machine that looked perfectly fine locally. **This actually happened:** a single regeneration removed **2532 lines** from the lockfile and broke CI, and nothing about the local run hinted at it. So:
- **Edit the lockfile IN PLACE.** `npm install` applies an `overrides` change to the existing tree without pruning the optional entries, so an override bump or a pin is a small, reviewable diff. **A lockfile diff that deletes hundreds of lines you did not intend is the tell** — read the diff before committing it, every time.
- If a full regeneration is genuinely required, do it **under Linux/CI parity** (the CI container or WSL), never from Windows.
- **`npm install` reporting "up to date" does NOT mean the overrides were re-resolved.** npm can consider the tree satisfied and skip re-resolution entirely, so a pin appears applied while the lockfile still carries the old version. Verify against the lockfile itself (`npm ls <pkg>`, or read the entry) rather than trusting the summary line.
